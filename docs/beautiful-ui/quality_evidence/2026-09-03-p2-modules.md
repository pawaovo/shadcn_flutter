## Interface and ownership

- All seven composites leave through `beautiful_ai_ui.dart`; public types do
  not expose `shadcn_flutter`. `implementation/streaming/stream_content.dart`
  stays internal and uses Flutter selection infrastructure.
- Streaming content/source IDs/lifecycle/feedback, tool execution snapshots,
  task status/progress, chat messages/response IDs, table rows, and accepted
  fine-tune settings belong to the host. No agent, transport, file execution,
  approval backend, or generated reply is part of the package.
- Approval owns question drafts and navigation, seeded by `initialAnswers`.
  Chat owns its draft and reading position. Filter Table owns the local status
  filter initialized by `initialStatus`; `onFilterChanged` observes changes.
  Fine-tune emits complete proposed settings and waits for host acceptance.
- Approval submission, task retry, chat send/stop, and streaming retry report
  recoverable failures through `BeautifulUiScope.onFailure`, tagged with
  `approval`, `taskRetry`, `chat`, and `streaming`. Streamed copy uses the
  existing `clipboard` operation and can be replaced by a host callback.
- Pending actions de-duplicate activation and ignore completions invalidated
  by their documented model, task, answer, conversation, or response identity.
  Host execution state never advances because a presentation callback ended.
- A private text-selection helper provides Flutter touch handles, selection
  gestures, localized 48dp clipboard menus, and the same guarded copy/cut/paste
  route for keyboard and native Semantics actions. Delayed reads cannot change
  a replacement conversation or question even when its text is identical.
  A failed cut preserves the draft and reports a `clipboard` failure.

## Source scope and intentional deviations

The source registry JSON was inspected in a local checkout whose HEAD is the
fixed source commit above. Exact TSX source paths and consulted shared atoms
are recorded in `legal/component_provenance.yaml`; source assets, canonical
golden origins, and existing license pins are unchanged.

| Module | Implemented scope | Intentional Flutter adaptation |
|---|---|---|
| Streaming Text | Streaming, complete, and failed lifecycle; selectable exact text; ID-based citations; source disclosure; copy/retry; feedback; follow-ups | Immediate caller snapshots replace artificial token delays, blur tail, and caret. Inline markers describe their source; full-size source controls handle navigation. Demo artwork/URLs are omitted. |
| Approval Card | Single/multiple choice, custom answers, navigation, skip/dismiss/reopen, asynchronous submission, reset | Stable IDs preserve drafts on reorder. Single-choice auto-advance is configurable; multiple/custom answers require confirmation. Success follows host completion and failures retain drafts. |
| Tool Chips | Think/write/run/read kinds; pending/running/complete/failed states; output and file previews; show-more | One presentation, matching the source's lack of visual variants. Inline tap/keyboard disclosures replace portal/hover-only details, and caller snapshots replace scripted reveal. |
| Task Rows | Capsules and list variants; four host states; determinate/indeterminate progress; details; retry | Stable IDs preserve focus/disclosure across reorder and variant changes. Retry does not synthesize a task transition. Progress has visible and semantic wording. |
| Chat | User/assistant/system messages; optional context tabs and metadata; multiline draft; send/stop; latest action | Host-owned replies replace demo timers. Enter sends, Shift+Enter inserts a newline, and IME composition blocks submission. Pending completion clears only an unchanged submitted draft. |
| Filter Table | All/to-do/in-progress/completed filtering; derived counts; empty state; four fields | Compact/medium cards preserve every field; expanded mode exposes table semantics. The host supplies scrolling for long sets; sorting, editing, and virtualization are outside this module. |
| Fine-tune Card | Bounded numeric fields; row/column/grid layout; type choice; Edited marker | Controlled snapshots replace implicit local acceptance. Finite fractional values and steps are preserved. Direct entry, touch buttons, keyboard, scrubbing, and assistive adjustment share bounded values. Type choices are inline. |

Approval and Chat preserve draft state around keyboard/viewport changes.
Numeric drafts commit on Enter, Done, or focus loss; malformed values retain
validation feedback, Escape restores the accepted value, and composing input
is not rewritten. Hosts supply a scrollable parent for content-sized surfaces
such as long tables and fine-tune cards.

## Accessibility and behavior test coverage

Each public module has dedicated widget and Semantics test files. The tests
encode the following contracts; execution results are recorded separately
below so test presence cannot be confused with a passing run.

| Area | Contract exercised by tests |
|---|---|
| Streaming Text | Exact Unicode content and citation numbering, immutable snapshots, lifecycle actions, generation/copy invalidation, mouse selection and selection-toolbar copy, source and feedback semantics, labeled 48dp actions |
| Approval Card | Question/option identity, single/multiple/custom answers, immutable submission order, pending/stale callbacks, draft preservation, keyboard/IME, native touch selection, stale clipboard actions after question replacement, short keyboard viewport, checked/disabled controls |
| Tool Chips | Host-state rendering without execution timers, tap/keyboard/Escape disclosure, stable identity on reorder/resize, signed diff previews, show-more, localized live status, hidden semantics |
| Task Rows | Both variants, stable focus/disclosure, no invented progress, async retry isolation, motion policy and active-ring freezing, localized progress/step semantics |
| Chat | Trimmed/de-duplicated send, unchanged-draft clearing, conversation/response invalidation, stop failure, IME/multiline input, native touch selection, identical-text replacement during keyboard/Semantics paste, failed-cut preservation, controlled tabs, reading-position preservation, keyboard/resize, author attribution |
| Filter Table | Real counts, initial-only filter state, row snapshots, resize/focus retention, keyboard activation, immediate hidden-row removal, native count announcement, table/list structure |
| Fine-tune Card | Release-time numeric validation, complete controlled snapshots, bounds/fractional steps, malformed/IME drafts, Enter/Escape, touch targets, RTL scrubbing, stable field identity, assistive adjustment and endpoints |

The suite includes adaptive boundaries 599/600/1023/1024dp, long localized
content, RTL, 200% text scaling, light/dark or high-contrast cases, and motion
policy cases where applicable. These tests do not replace an actual
screen-reader, physical-device, or visual review.

Streaming lifecycle/copy feedback and Filter Table result counts use native
`liveRegion` labels without `SemanticsRole.status`. Flutter 3.47 forbids that
role/flag combination. Streamed answer and chat message bodies remain outside
live regions to avoid full-text announcements for each update.

## Catalog and shared integration journey

`packages/beautiful_ai_ui_catalog/lib/p2_examples.dart` supplies the demo
business state and callbacks for all seven modules. It includes live/complete/
failed answer scenarios, the three-question approval form, tool and changed
file details, both task-row variants, a send/stop conversation, a real status
filter, and a controlled fine-tune inspector. Simulated streams and replies
remain only in the non-published Catalog.

The Catalog widget tests and the existing Chrome/Linux/Android shared journey
have been extended to exercise P2 callbacks and verify visible host updates.
The local Chrome journey passed with Chrome `152.0.7977.66` and ChromeDriver
`152.0.7977.75` at 1440×900, DPR 1, using the desktop Web platform path without
mobile emulation. Remote Chrome, Linux/Xvfb, and Android execution passed in
both P2 runs `33701530733` and `33707996401`.

The final Wasm release was also inspected in a real browser: the Chat prompt
was editable and no browser error logs were present. The single-thread Skwasm
warning reflected the local server's isolation headers; this check does not
claim multithreaded Wasm deployment evidence.
