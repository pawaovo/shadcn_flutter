# P1 module-set evidence

Date: 2026-09-02 (Asia/Shanghai)
Branch: `product/main`
Toolchain: Flutter `3.47.0`, Dart `3.13.0`
Beautiful UI source: `dd1ba4f323c29ef6c383b2dbf1d7100f2c26ccac`

This evidence covers Thinking, Context Cards, Recommendation Card, Search,
and Code Block on top of the existing Foundation and Loading State slice.

## Interface and ownership

- All five modules are exported only through `beautiful_ai_ui.dart` and expose
  no `shadcn_flutter` type.
- Thinking status/items, Context chunks, Recommendation options, Search items,
  and Code/Diff content are caller-owned immutable snapshots.
- Disclosure, hover, focus, selection, keyboard highlight, pending state, and
  short-lived copy feedback remain package-owned presentation state.
- Host callbacks own source navigation, recommendation acceptance, search
  selection, and optional clipboard replacement.
- Recommendation and clipboard failures are normalized as
  `BeautifulUiFailure` and leave through `BeautifulUiScope.onFailure`.

## Intentional source deviations

- Thinking removes the embedded demo sequence timer; collapsed descendants
  leave focus and Semantics traversal.
- Context chunks use stable IDs, add compact long-body disclosure, and make a
  source actionable only when a host callback exists.
- Recommendation accepts structured string content instead of arbitrary
  `ReactNode`/`Widget` content and commits accepted state only after an
  asynchronous callback succeeds.
- Search uses stable typed items and adds ArrowUp/Down, Enter, Escape, IME
  composition protection, selected Semantics, and a host selection callback.
  The public module is inline; the host owns dialog/popover/sheet placement.
- Code Block uses named Code/Diff constructors and one canonical code string.
  Long lines remain unwrapped in a horizontal viewport. Copy is de-duplicated
  while pending and Diff meaning is announced without relying on color.

## Real browser evidence

The shared `integration_test/catalog_journey_test.dart` passed through Flutter
WebDriver using Chrome `152.0.7977.66` and ChromeDriver `152.0.7977.75` at
1440×900. It launched the real Catalog, verified all Loading entries, cycled
theme and motion, collapsed Thinking, invoked a Context source callback,
opened and accepted a Recommendation, filtered and selected a Search result,
copied Code Block content, and completed without a framework exception. The
desktop run fixes DPR with a Chrome flag rather than mobile emulation, so it
retains the desktop Web platform path.

Flutter 3.47 rejects `flutter test -d chrome integration_test`; the supported
Web path therefore uses a matching ChromeDriver, `flutter drive`, and the
`web-server` device. Linux uses Flutter Test under Xvfb. Android uses the same
target through an emulator.
